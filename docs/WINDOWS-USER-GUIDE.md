# Vault 443 1.3.5 для Windows

Нужна Windows 10 22H2 x64 или Windows 11 x64. Установщик и контрольные суммы
доступны в [релизе 1.3.5](https://github.com/RealLeo/vault443/releases/tag/1.3.5).
Qt/QML, runtime-библиотеки, VPN-движки и официальный подписанный Wintun включены;
устанавливать SDK, Go или Qt отдельно не требуется.

В 1.3.5 появились выбор локального диска и папки установки, иконка EXE и
издатель **Vault 443** в метаданных и списке приложений. Приложение и установщик
не имеют Authenticode-подписи: метаданные не делают издателя подтверждённым в UAC.
[Изменения и статус проверки 1.3.5](RELEASE-1.3.5.md#validation).

Прежняя сборка R9 версии 1.3.4 остаётся в
[своём релизе](https://github.com/RealLeo/vault443/releases/tag/1.3.4).
Её приёмка Windows 10/11 сохранена в
[историческом отчёте](WINDOWS-ACCEPTANCE-REPORT-2026-11-07.md);
он не заменяет проверку установщика 1.3.5.

## Установка

1. Скачайте [установщик Windows x64](https://github.com/RealLeo/vault443/releases/download/1.3.5/Vault443-1.3.5-windows-x64-setup.exe)
   и его [SHA-256](https://github.com/RealLeo/vault443/releases/download/1.3.5/Vault443-1.3.5-windows-x64-setup.exe.sha256).
2. Получите хеш в PowerShell:

   ```powershell
   Get-FileHash .\Vault443-1.3.5-windows-x64-setup.exe -Algorithm SHA256
   ```

   Сравните его с хешем из скачанного файла `.sha256`.
3. Запустите установщик из обычного пользовательского сеанса и подтвердите UAC.
   Выберите локальный диск и папку приложения. По умолчанию используется
   `C:\Program Files\Vault443`; можно выбрать, например, `D:\Apps\Vault443`
   или каталог с пробелами и кириллицей.
4. Откройте Vault 443 из меню «Пуск». Служба `Vault443` работает от
   LocalSystem (SYSTEM), окно — от обычного пользователя. Повышать права при
   каждом запуске не нужно.

Установщик проверяет путь и защищает принадлежащие приложению файлы от подмены
обычным пользователем. Сетевые пути, junction, символические ссылки и небезопасные
родительские каталоги не подходят для размещения службы SYSTEM. При отказе
выберите другую папку на локальном диске; права посторонних каталогов установщик
не меняет. При обновлении сохраняется прежний каталог установки.

При обычной интерактивной установке UAC подтверждает установку службы и
предоставление доступа текущему пользователю. Если установка выполнена
автоматически от SYSTEM, первый запуск может отдельно запросить UAC.
Административные настройки, включая загрузочное подключение, также могут
требовать подтверждения.

## Профили и подключение

Для основного VPN импортируйте `vless://`, `trojan://`, `ss://` или `ssconf://`,
текстовый файл либо HTTPS-подписку. Проверьте предварительный список и сохраните
профили. Для рабочих VPN импортируйте конфигурации WireGuard/AmneziaWG или файл
OpenVPN `.ovpn`; поддерживаемые автономные ключи `vpn://` можно вставить при
импорте. Выберите профиль, запустите подключение и дождитесь конечного состояния.
При ошибке откройте журнал соответствующего профиля.

Одновременно используется один основной VPN и до 16 рабочих туннелей суммарно.
Рабочие сети и DNS-зоны направляются через соответствующий VPN. Пересекающиеся
маршруты или зоны могут потребовать выбора владельца в настройках маршрутов.
Рабочий полный туннель приостанавливает основной VPN; после его отключения
основное подключение может восстановиться.

OpenVPN использует поставляемый движок с Wintun. WireGuard и AmneziaWG используют
поставляемые Go-движки и Wintun; Linux-драйверы и `wg-quick` в Windows не нужны.
Импорт OpenVPN поддерживает сертификатные TUN-профили со встроенными ключами и
сертификатами; пароли, MFA/SSO, TAP, пользовательские скрипты и плагины не
поддерживаются. Подробности форматов приведены в [документации рабочих VPN](work-vpn.md).

Запуск окна при входе в Windows и подключение основного VPN при загрузке системы —
разные настройки. Для второго отдельно выберите загрузочный основной профиль.
Рабочие VPN после перезагрузки запускаются вручную; перезапуск службы в пределах
той же загрузки восстанавливает запрошенные подключения.

В общих настройках доступны русский, английский и системный язык. Закрытие окна
не отключает VPN: используйте значок в трее или повторно откройте приложение.
Для освобождения сетевой защиты явно отключите подключения в интерфейсе.

## Обновление и удаление

Для обновления запустите новый проверенный установщик поверх существующей версии.
Профили, настройки и каталог установки сохраняются; служба может перезапуститься.
Обновление 1.3.4 → 1.3.5 не требует повторного импорта профилей.

Для переноса на другой диск или в другую папку удалите приложение штатным
способом, затем установите его в выбранный каталог. Приватные профили и журналы
в `%ProgramData%\Vault443` сохраняются по умолчанию, независимо от папки EXE.

Удаляйте Vault 443 через «Параметры → Приложения → Установленные приложения».
Установщик сначала штатно закрывает точный GUI через Restart Manager и проверяет
его завершение. Если окно зависло или не может закрыться, удаление прерывается
до остановки службы и сетевой очистки; принудительное завершение не применяется.
Выберите выход из интерфейса в трее и повторите удаление. После закрытия GUI
удаление очищает только принадлежащие приложению сетевые ресурсы; при ошибке
также прерывается и сохраняет файлы и профили для повторной попытки.

## Диагностика

Начните со строки состояния профиля, диагностики и журнала в приложении.
Состояние службы можно проверить в приложении «Службы» или PowerShell:

```powershell
Get-Service Vault443
```

Если служба не запускается после обновления, повторно запустите проверенный
установщик для восстановления. Администратор может посмотреть журнал службы
`%ProgramData%\Vault443\service.log`. Профили и журналы в ProgramData приватны;
обычный пользователь получает свои данные через защищённый IPC приложения.

Контрольные суммы, манифесты сборки и точные исходники сопровождают выпуск.
Технические инструкции приведены в [WINDOWS.md](WINDOWS.md), статус текущих
проверок — в [заметках 1.3.5](RELEASE-1.3.5.md#validation).
